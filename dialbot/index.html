Beyond the answer

In the flow
of the meeting.

Speak, type, ask for a room action, or point to what is being shared. Open a line to see how it could work.

01Private chat with Dial Bot.A conversation only you can see.

Open a private thread with Dial Bot in the meeting chat. Ask a question and see its reply there, without posting either to the group.

02Say its name.Use a clear spoken wake phrase.

Begin a spoken request with “Hey Dial Bot” to make clear the question is for it: “Hey Dial Bot, what’s still pending?”

03Leave room for the question.A brief window for the same speaker.

If someone says only “Hey Dial Bot,” it can answer “Yes?” and give that speaker a brief moment to ask the question without repeating its name.

04Move the meeting along.Requested timer and room controls.

Ask Dial Bot to start a shared timer; a host or co-host can also request a room title change. The result appears in the meeting without an unnecessary spoken announcement.

05Ask about what is showing.A fresh look at the shared screen.

When asked about the shared screen, Dial Bot checks a fresh frame for that question so its answer reflects what is showing now.

06Visible in the room.Invited by the host, present with the team.

The host invites Dial Bot as a visible meeting participant; its tile stays with the group and waits quietly for a request.

07Bring the issue into focus.A specific source for the answer.

A Jira issue shared for the question gives Dial Bot a specific source to answer from and link back to. The connection and sharing flow are still being explored.

Open-draft capabilities and UI studies, shown with fictional meeting details. These examples are not shipped product behavior.

The right context.
Only when shared.

Each person should choose what Dial Bot may use. Glean is planned for broader context; this local draft tests Jira access. Answers should point back to their sources.

Before changing a Jira assignee, Dial Bot would read back the exact change and ask the right person to confirm.
