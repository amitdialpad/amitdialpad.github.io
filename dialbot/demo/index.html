    Try Dial Bot in a beta meetingInternal local setup

    This is a local, nonproduction test. You need a compatible uc_client checkout, approved npm access, Chrome, the trusted local development certificate, and a beta account that can host a meeting. Spoken requests also need Voice AI transcription enabled with everyone’s consent.

    Set it up manually

    1. From uc_client/, run npm ci and complete the approved local certificate setup.
    2. Create an owner-only ~/.dialbot/dialbot.env file outside the repository and a fresh pairing file. Both files must be mode 0600. Add these settings to the environment file, replacing the placeholders with approved values:
      DIALBOT_BRAIN_MODEL=<approved-model-name>
DIALBOT_OPENAI_API_KEY=<project-scoped-server-key>
DIALBOT_LOCAL_SECRET_FILE=$HOME/.dialbot/host-pairing-secret
DIALBOT_GUEST_LOCAL_BUNDLE=1
      Load the same pairing-file path in both processes.
    3. Load that environment file in two terminals. Start the local client with npm run dev in one and the launcher with node scripts/dialbot-local/server.mjs in the other. Use the port requested by your beta page.
    4. Start a beta meeting. In Host Controls, choose Dial Bot → Invite. Try “Hey Dialbot” or send a private chat message. Use Remove when finished.

    With Claude Code

    Open the same checkout and ask Claude Code to walk through uc_client/scripts/dialbot-local/DEMO.md and the launcher README.md. Keep keys and the pairing value in local owner-only files or the approved secret manager, never in the chat, browser URL, or repository. Review the commands before running them.

    Before you test

    A natural voice needs the approved voice configuration; without it, the launcher may use a test voice. This audited build is meeting-only. Personal Jira, Glean, and Calendar account connections are not enabled here; check the current internal guide for any separately approved branch.

    If it does not connect: Check that the local client and launcher loaded the same pairing-file path. If the guest asks for a name, verify DIALBOT_GUEST_LOCAL_BUNDLE=1 and the local client port. If speech does not wake the Bot, check Voice AI transcription and the wake phrase. If the browser blocks the local bundle or WebSocket, use an approved preview instead of bypassing the block. Live spoken answers and voice quality still need to be checked in a real room.
