02 THE WORKLOOP

Made for a pod
that builds together.

One task moves between people. Its decisions, progress, QA proof, and next move stay together, so the next builder knows where to begin.

Today: shared activity and QA results. Next: automatic handoff when work gets stuck.

No one starts from zero.Start with your project ↗
03 START IN YOUR PROJECT

One instruction to start.
Two ways to keep moving.

Paste the instructions into your coding agent. Ask for a real plan update and QA run before calling setup complete.

Set up Workloop in this repo using https://amitdialpad.github.io/virtual-pm/agent-setup.md. Install its shared plan and QA checks, map our real tasks and scenarios, then prove a branch-push plan update and a QA report. Never mark Done from a commit or test alone.

02 / QA CHECKS

Check the proof.

Mapped scenarios show pass, fail, or not run, with gaps kept visible.

Setup guide →

See the instruction

Set up Workloop's QA checks beside our shared plan using https://amitdialpad.github.io/virtual-pm/qa-setup.md. Map each real use case to a plan task, add the code checks we can actually run, leave live user proof explicit, and show me the first report and a GitHub Actions run. Do not call unmapped cases passed.

Code activity and mapped checks update automatically. People still record decisions and decide when work is Done.
