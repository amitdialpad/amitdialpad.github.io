ONE FILE. ONE SHARED VIEW.
01 / The idea

Four builders.
One understanding.

Work moves fast. The context around it gets scattered across messages, code, task boards, and someone’s memory. Virtual PM brings the product story and delivery status into the same place.

01

Know the promise

The experience we want to create stays visible next to the implementation.

02

Know the owner

Every piece has a person responsible and a clear next proof.

03

Know what changed

Decisions and tradeoffs are recorded as the team learns.

04

Know what works

“Done” means demonstrated, with evidence someone else can inspect.

The operating principle

Make the plan part of the work, not another place to report the work.

↗
02 / How it works

A project rhythm
built into every change.

Virtual PM is a Markdown file in the same shared branch as the project. People and their coding agents read it before building and update it when work changes.

↘
01 / Start here

Read the whole story

Open the file for the goal, scope, decisions, owners, current state, and open questions.

↗
02 / Make the change

Update the same file

In the same contribution, update your task’s state, next proof, blocker, and evidence.

✓
03 / Check the claim

Prove before “done”

Attach a test or review result. An agent can audit the file against code and evidence when asked.

✳

The file does not change by itself. The team’s contribution rule keeps it current; agent reviews help catch drift.
